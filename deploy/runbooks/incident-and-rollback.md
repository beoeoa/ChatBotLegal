# Feature 018 incident and rollback

Stop traffic promotion when any readiness, legal, security, restore, load or
UAT gate fails. Preserve audit and release history.

1. Freeze canary percentage and capture content-free timestamps/statuses.
2. Route traffic back to the last fingerprinted frontend/API images and active
   legal/form/FAQ/vector pointers.
3. Do not disable validity, authority, role, procedure, citation, checksum or
   audit checks to recover availability.
4. Verify citizen, officer and Admin smoke paths against the prior release.
5. Open an incident record with release IDs, hashes and reason; never paste
   questions, answers, credentials or attachment content into monitoring.

Database rollback uses release pointers/flags. It must not hard-delete legal,
FAQ, form, lifecycle, support-audit or checkpoint history.
